How each kind of item is written

Both sides Colleague email

Written into the sender's Sent Items and every internal recipient's Inbox, with one message ID and the original time, unread for recipients. Adelia's Copilot sees what she asked; Carlos's sees what he received.

Inbox only Outside or system email

Written into each internal recipient's Inbox with the outside sender's name and address, unread, not a draft, with the original time and any attachments.

Import Teams chat

A [Triage] group chat is created with its members, then every message is imported as its author at its original time. Once finished it's a normal chat people can reply in.

Runbook

  1. Pre-flight. One admin device-code sign-in. Check the tenant, that all 16 people exist and are licensed, and write down Carlos's current unread count (existing mail is never touched).
  2. Raise access for the run; wait for it to take effect; check with a new token.
  3. Small test first: 1 outside email, 1 both-sides email, 1 [Triage] chat with 3 messages. Check in the browser as Carlos: unread, right time and sender, not a draft, chat authors right.
    Stop if anything looks wrong.
  4. History: files (upload, set Tags, share), past and upcoming calendar events, chats T1 to T4, history emails H1 to H6.
  5. Morning inbox: the 40 emails, oldest first, with attachments.
  6. Check: counts per mailbox, both sides present, tags present, chats visible, Copilot can find a chat and a file. Save the run list.
  7. Lower access to read-only and confirm a send attempt is refused.
  8. Report, then hand over for the Premium, Cowork and Scout tier tests.

Undo

  • One command, one admin sign-in: deletes every item tagged Triage in every mailbox and calendar, plus drafts replying to them, and the seeded files with their shares.
  • Teams: imported messages are deleted; the empty chats are renamed "[Triage] (removed)" and all but one member removed, because Teams keeps empty chats.
  • Existing mail, files and chats that weren't seeded are never touched.

Read-only lets me grade the tier tests without another sign-in. The app is removed when validation is done, or when its certificate expires on 29 Oct.

6
Visible "Triage" category on emails?
A visible category would show on every email in Carlos's inbox during the demo, and Copilot may read it as "already triaged", which spoils the triage. The hidden property is just as reliable for cleanup and can't be seen.
Also: no visible "FICTIONAL" banner in email bodies or inside files, so they read like real work. Emails carry a second hidden property DemoData = FICTIONAL; files carry it in their Tags.
Recommended: hidden property only on emails; visible [Triage] on chat names, file Tags and calendar categories
